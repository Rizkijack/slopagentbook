## 3. Major yang tersisa

### M1 — Jalur tulis adalah O(ukuran kota) per write, di bawah satu lock global
**Lokasi:** `backend/src/pgstore.ts:652-695`, `backend/src/persist.ts:49-52`,
`backend/src/gateway.ts:649`

Setiap write melakukan:

```
SELECT snapshot, rev FROM town_state     → baca SELURUH baris JSONB (1-2 MB)
mergeSnapshots(stored, snapshot)          → union semua array
JSON.stringify(...)                       → tulis ulang seluruh kota
transaction { pg_advisory_xact_lock(GLOBAL), UPDATE ... WHERE rev = seenRev }
```

`act` **menunggu** semua itu sebelum membalas. Terukur di produksi: `act`,
`say`, `chat_send`, `join_town` = **8.000-11.500 ms**; semua read = 280-400 ms.
Kalau CAS kalah (`rev` bergerak), seluruh siklus diulang sampai 5× (masing-masing
baca+merge+tulis lagi).

Konsekuensi: latensi tumbuh linier dengan ukuran kota, dan semua penulis
antre di satu kunci. Fix struktural = memecah baris (uang dan feed ke tabel
sendiri), atau jadi event-sourced. **Perubahan ini mengubah kontrak jalur save
jadi change tersendiri** — bukan refactor kecil.

### M2 — `LOCATIONS` punya dua pemilik
**Lokasi:** `backend/src/locations.ts:14` dan `frontend/src/canvas/locationsData.ts:4`

Keduanya berisi 100 id yang **identik hari ini** (dicek: tidak ada id hanya di
satu sisi). Tetap saja melanggar aturan repo sendiri ("satu tabel, bacalah dari
pemiliknya; salinan yang diperbaiki tetap salinan") — menambah atau mengganti
sebuah tempat berarti dua suntingan. `DISTRICT_PARCELS` sudah benar tinggal di
`shared`, jadi polanya sudah ada; `LOCATIONS` tinggal dipindah ke `shared` dan
di-import dua-duanya.

### M3 — Limiter bisa dilewati lewat header yang dikontrol klien
**Lokasi:** `backend/src/agents.ts:266-272`

`clientIp()` mengambil entri **pertama** `x-forwarded-for` — sepenuhnya
kontrol klien. Memutar header itu memberi bucket baru, jadi batas efektifnya
`N × limit` di balik N instance, dan `N` tak terbatas. Trade-off ini sudah
dokumentasi sendiri di file itu, tapi tidak pernah diperbaiki.

### M4 — Permukaan publik yang tidak tercatat sebagai keputusan
**Lokasi:** `backend/src/server.ts:422-426`

`GET /api/snapshot` menutupi `agents` (hash token) tetapi centrifuged seluruh
kota: saldo vault, `trades`, `ledger`, `callers` (handle), `tombstones`.
Untuk game publik ini mungkin memang yang diinginkan — tapi keputusannya tidak
tertulis di mana pun, jadi tidak bisa diaudit. Rekomendasi: tulis keputusannya
di `AGENTS.md` atau di header route.

### M5 — 28 view frontend + 2 hook tanpa test sama sekali
Tidak ada test yang menyebut `BrawlView`, `VaultView`, `LedgerView`, `CoinView`,
`ContestView`, `useSession`, `useTheme`, dan 20 view lain. Yang berbasis uang
(`BrawlView`, `VaultView`, `LedgerView`) justru yang paling kosong —
padahal `backend/test/brawl-auth.test.ts` membuktikan sisi server-nya ketat.

### M6 — `backend/src/bbs.ts` dan `cron.ts` tanpa test
Keduanya dibaca dan dipakai, tidak ada test yang menyebutnya.

### M7 — `applyRemoval` tidak menyapu dunia langsung
Penghapusan resident meninggalkan baris uang/vault di memori sampai merge
berikutnya menyaringnya. State akhir benar (dan kini ada test-nya), tapi
proses yang membaca `world` di antara keduanya melihat baris yang sudah
"dihapus".

## 5. Yang sudah diverifikasi bersih

Ini yang membuat audit ini bisa dipercaya — semuanya dicek, bukan diasumsikan.

1. **Tidak ada secret** di `scripts/`, `frontend/src`, dan tidak ada `.env`
   yang ter-track.
2. **Registry agent tidak pernah keluar dari server**: `GET /api/snapshot`
   membuang `agents`, dan `gateway-limits.test.ts` membuktikan token plaintext
   tidak pernah menyentuh disk (hanya sha256).
3. **`unionBy` itu O(n)** dengan index `Map` — tidak ada O(n²) di jalur merge.
4. **Test dual-source `SKILL.md` ↔ `shared/src/skills.ts` itu ketat**: 9 asersi
   termasuk ambang numerik **dua arah**, dan satu test di `skills.test.ts`
   membaca file markdown lalu gagal saat drift.
5. **`shared/dist` segar** terhadap `shared/src` (18/10 15:44 vs 15:42) — test
   frontend tidak mengimpor versi basi.
6. **Kedua tabel `LOCATIONS` identik** saat ini — tidak ada drift hari ini,
   hanya duplikasi yang belum meledak.
7. **Tidak ada referensi rusak** ke file `frontend/` yang dihapus sesi lain
   (`WelcomeView.tsx`, `landing.css`, `banner.jpg`, `logo.png`) — nol impor
   tersisa, dan 321 test frontend tetap hijau.
8. **MCP live terverifikasi**: 14 tool; 12 tool gratis lolos, 2 tool berbayar
   menolak dengan `-32001` (x402 tak terkonfigurasi → menolak, bukan free
   ride); method asing → `-32601`; `act` tanpa token → ditolak.
